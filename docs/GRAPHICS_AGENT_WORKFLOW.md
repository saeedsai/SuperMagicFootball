## Actual tool contract

SuperMagicAssetStudio is the authoring and export tool. Its current CLI includes rig/joint/part binding, poses/motions/frame sampling, PNG/GIF/sprite-sheet rendering, project review and image splitting. Image splitting is geometric/alpha-based; it does not identify anatomy, direction or animation. The renderer uses independent 2D parts and hierarchical transforms with linear frame sampling. It currently has no inverse kinematics, automatic weights, mesh deformation, foot locking or cross-view retargeting.

For a change in Studio, confirm live operations with `node src/cli/agent-cli.mjs --list-ops`, then use actual CLI/browser operations and inspect rendered pixels. Run Studio's `npm test`, `npm run test:contracts`, and browser suite where available. Do not infer a command from old instructions or claim Studio compatibility from handmade JSON parsing.

The supplied project JSON files passed the actual CLI `review` operation and rendered through official CLI exports. Opening the external-reference JSON in the browser editor showed an empty canvas and the UI reported 148 unresolved PNG files. Converting the project with the official CLI `setImageStorage mode bundled` operation made the same Alex project open with its character visible in the browser editor. Use bundled mode for self-contained review packages; test `Resolve external images` when keeping external mode. The automated browser suite was not run because Python/Playwright is unavailable in this environment. Full results and the visual evidence are in [the dated audit](GRAPHICS_ASSET_AUDIT_20261031.md).

The first generated 17-part atlas, bodybuilder source-cut rig and detailed 13-part arm rig are **rejected** for the production path; the 13-part front arm test opened seams and exposed stray jersey pixels. The active fallback is exactly three visible modules per frame: (1) one complete body image with the head removed, (2) the bald face/head, and (3) the hair. Do not split the body into limbs or add anatomy modules. Build each frame from that frame's complete original pose, cut/reconstruct only within its source bounds, and place all three modules back at their original coordinates. Never carry a mask, crop, geometry, or offset from another pose as a production cut; a transformed mask may be used only as a temporary fit hypothesis and must be redrawn against the current source before acceptance. Where hair hides the scalp, reconstruct only the missing bald scalp in the head module and retain source pixels for the visible face, ears, and neck. Keep the complete pose as a hidden comparison reference. Every required frame needs its own three modules unless a specific head/hair asset is explicitly reused after a source-to-assembly image comparison and visual fit review. The complete body cel remains frame-specific unless the exact image, kit, pose, and scale are identical. Reuse across views or players is conditional on identity, projection, pose, scale, lighting, occlusion, and landmarks; mirror only after checking every asymmetric detail. The three-module rule applies to all eight views and every action/keyframe, with the coverage matrix recording source, module presence, reuse evidence, defects, and approval state. Studio structural validity does not imply art acceptance, and no module is approved merely because its pose was assembled.

## Asset and motion rules

1. Translate the supplied compact illustrated roster reference into an approved proportion sheet before production: canvas and ground line; head-to-body ratio; head height/width; shoulder and pelvis width; torso, arm and leg lengths; and head, neck, shoulder, elbow, wrist, hip, knee, ankle and toe landmarks. Keep athletic anatomy readable and human-like within the stylized proportions. Derive dimensions and joint pivots from this sheet so counterparts and players keep the same scale.
2. Produce and review one complete neutral master that follows the reference style before cutting parts. Compare assembly against the exact source at full size and game size. For the three-module path, preserve full body geometry in one image and isolate a bald head and hair overlay. Head/face geometry and hairline must match the source; masks must exclude neighboring facial features unless the art intentionally assigns them to the head module. Reject proportion, alignment or color drift.
3. Draw a complete source player independently in each of the eight true views: front, front-right, right, back-right, back, back-left, left and front-left. Do not count rotated or mirrored front art as authored views when details, anatomy or depth change.
4. Cut and reassemble exactly three modules from each complete source pose: (1) one complete headless body image, (2) bald face/head base, (3) hair. Use AssetStudio's `partitionImage` operation to keep each cut full-canvas, source-aligned, disjoint and completely covering all visible source pixels; import all modules with a shared transform. Work from the exact frame being assembled. Do not transfer production masks or offsets between frames; trace/refine the cuts against that frame, reconstructing scalp pixels hidden by hair when the bald head must support other hairstyles. Keep the modules at source coordinates and keep a hidden full-pose reference. Prove the assembled front against its source, then validate another true view before scaling to the remaining directions. A view does not count as modular if its bald-head base secretly contains visible hair or depends on the overlay to conceal a defective cut. Every required view/action/keyframe must resolve all three modules, either as authored assets or as a specific compatible reuse reference with recorded comparison and visual review. Reuse head or hair across frames, views or players only when identity, projection, pose, scale, lighting, occlusion and source landmarks match; store each approved reuse link in the manifest. Share a hair/head style only when it is intentionally the same asset. Reuse a body image only when body geometry, kit, number/marks and pose all match. Mirror only after checking asymmetric anatomy, hair part, text, numbers, crests, handedness and perspective. If a fit fails, make a frame-specific module; never stretch a flat image or force an old mask to fit.
5. Author and review animation across time: planted feet, weight transfer, contact frames, recovery and loop seams. The current 2D rig is not a substitute for missing anatomy or view-specific artwork.
6. Record asset ID, category, view, dimensions, pivot/landmarks, source/provenance, permitted reuse, export command, Studio version and game-side path in a manifest.

## Studio-to-game acceptance gates

- **Package audit:** inspect all project JSON, source parts and reports in the supplied ZIP. Import/reopen it in the official Studio and run its real CLI/browser review/export. Keep the package's previous status labeled `NOT APPROVED` until this succeeds.
- **Character master:** inspect a neutral full-body view at game scale on light, dark and checkerboard backgrounds. Record owner visual approval separately from automated checks.
- **View and action coverage:** use a matrix for 8 views × actions × frames. A generated preview, deformed stand sprite or placeholder must be marked `NOT AUTHORED` and cannot fill a production coverage cell.
- **Automated asset integrity:** decode every export; check alpha, bounds, dimensions, paths, manifest references, duplicate/missing parts, stable view IDs and finite transforms. From the game repo root, batch-check every project linked by the coverage matrix with `node ../references/analysis/player_master_pilot/front_three_module_pilot/validate_covered_projects.mjs`; this checks each candidate frame's three modules and runs the official AssetStudio CLI review. Validate one candidate directly with `node ../references/analysis/player_master_pilot/front_three_module_pilot/validate_three_module_project.mjs <project.json> <view> <animation> <frame>`. For source-locked bald-head candidates, use `node ../references/analysis/player_master_pilot/animation_three_module_pilot/measure_bald_hair_overlap.mjs <project.json> <view> <animation> <frame>` to flag source pixels retained in the head inside the hair mask; inspect flagged pixels visually because overlap scores are diagnostic. For same-renderer source/assembly PNG pairs, use `../../references/analysis/player_master_pilot/animation_three_module_pilot/compare_source_assembly_png.mjs` to report RGB deltas and missing/extra silhouette pixels at both full and game sizes.
- **Module separation gate:** verify the assembled source comparison and inspect each isolated module. A pixel-exact composite can hide hair assigned to the body or bald head. The headless body must have no head/hair fragments; the bald face/head must contain a coherent scalp beneath the hair with no visible hair remnants; hair must contain the intended hair shape without face/kit spill. For the exact-partition tackle_05 pilot, run `node ../references/analysis/player_master_pilot/animation_three_module_pilot/validate_exact_three_module_partition.mjs`; it checks three modules, disjoint masks, source coverage and pixel-exact AssetStudio output, but it does not replace visual purity review. Record separation defects per frame and do not approve or reuse a module until both the assembled image and isolated parts pass visual review.
- **Visual review:** render contact sheets and full-speed previews through Studio, then use the exported assets in the actual game on desktop and simulated touch. Check anatomy, seams, clipping, aliasing, timing, visibility at playable size and browser errors.
- **Integration:** verify fallback for missing/bad assets, offline cache behavior, saved appearance compatibility, and no unintended gameplay/hitbox changes. Run focused and exact-head game regression.
- **Completion:** mark a view/action approved only after automated integrity, actual Studio render/export, game integration review and human art acceptance all pass. Retain failed examples and name limitations.
