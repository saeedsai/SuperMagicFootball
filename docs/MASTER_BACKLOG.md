## Owner priorities and invariants

- Prioritize playable gameplay and abilities, existing in-game player graphics/animation, VFX/stadium/pitch, responsive/accessibile UI, Career/Cup, and online functionality.
- Keep the existing Home/menu character art and supplied reference layout; the owner said that art is good and asked that effort go to gameplay and ball/player visuals.
- Defer player/team identity audits, roster validation and player-stat tuning. Skip new Concept Hero/Royal Concept teams and all new concept-hero creation.
- Preserve offline play, save compatibility, roster identities/order, six formations, keyboard/touch/gamepad access, accessibility and the existing four-action input schema.
- SuperMagicAssetStudio is the source-art tool. The game consumes only approved exported assets/manifests; keep the procedural renderer as fallback. Structural checks do not imply owner visual approval.
- Do not claim visual approval, physical-device acceptance, protected promotion, hosting or server readiness without evidence.

PVP now has a bounded same-match recovery window after an unexpected transport loss: the server pauses simulation, a newly authenticated one-use ticket restores the disconnected user to their original side and latest authoritative snapshot, input sequence resets for that seat, and a grace timeout closes the match without settling a result. See [candidate .34 validation](CANDIDATE_012834_VALIDATION_20261104.md), [ball projection evidence](BALL_PANEL_PROJECTION_20261104.md), and [candidate .33 validation](CANDIDATE_012833_VALIDATION_20261104.md) for preceding Career/UT/server functionality.

Online Career is playable through the server: a signed-in user can start a server-owned eight-fixture season with an owned team, read fixtures and standings, and request the next pre-bound fixture. Only a matching durable result advances the season, idempotently; Career fixtures use server CPU while PVP pairs two human players. Online UT equips twelve unique canonical players in role-compatible slots; versioned, idempotent lineups are server-validated, ticket-bound and used by authoritative simulation. The local squad-copy workflow remains separate.

The authenticated result reward derives completion/win/draw tokens from immutable stored scores and commits capped balance plus an idempotent receipt. Local tests do not verify a live PostgreSQL database, configured OIDC provider, public network, multiple devices, horizontal/multi-process matchmaking, crash recovery, deployment or human visual/device acceptance. The connected Render workspace has an existing LAN signal service and no PostgreSQL database. A standalone Free account/match API Blueprint is in `render.online.yaml`; the existing `render.yaml` LAN service definition remains unchanged. The recommended closed-test stack is Render Free + Supabase Free Postgres + Auth0 Free OIDC. Render sleeps after 15 minutes without inbound traffic; Supabase Free has no automatic backups and may pause after a week of low activity. This is a prototype path, not durable production hosting. No Supabase project or Auth0 tenant has been provisioned; API database/OIDC settings and browser client configuration remain empty, so sign-in cannot safely be enabled until external accounts are configured. No real-money token purchase is enabled. Offline play and saves remain independent. See [online server deployment handoff](ONLINE_SERVER_DEPLOYMENT.md).
